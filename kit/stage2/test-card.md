# 阶段2 双机测试卡（E2/M2）

> 两人同时在线；全程约 30–60 分钟。测试期间游戏照常用 Steam 启动，EAC 保持开启。
> 本卡同时给志愿者与主持方；失败时按 §5 的顺序止损。

## 0. 测试前 10 分钟（双方各自）

| # | 动作 | 通过标准 |
|---|---|---|
| 1 | 跑 `selfcheck.ps1`（B 路线加 `-RouteProxy`） | 全部 `[OK]` |
| 2 | 断开 Radmin VPN / 任何 VPN、加速器；确认没有系统代理残留（A 路线） | `selfcheck` 里 VPN/代理项通过 |
| 3 | 正常启动一次游戏，确认 EAC 不弹错、能进主界面 | 进到主界面后退出 |
| 4 | 双方在 Steam 互为好友（主持方确认） | 好友可见 |

## 1. 启动（主持人先）

1. 主持人启动游戏，进入**飞船/主界面**；
2. 打开游戏内社交/大厅界面，**创建大厅**（Public 或 Friends only 均可，建议先 Friends only）；
3. 记录：创建时刻、界面有无报错、`%APPDATA%\Arrowhead\Helldivers2` 下最新日志文件名；
4. 观察 30 s：大厅是否稳定存在（不闪退、不自动关闭）。

## 2. 加入（志愿者）

1. 志愿者的游戏在主界面 → 社交界面应能看到主持人的大厅（好友列表或大厅浏览器）；
2. **加入** → 观察：是否进入同一大厅、成员列表是否出现两人；
3. 记录：加入时刻、是否有报错弹窗（截图）、多久进入大厅。

## 3. 进局

1. 主持人选择任务 → 邀请/等待志愿者 → 两人都进入同一任务；
2. 记录：任务加载耗时、是否出现不同步/掉线、能否完成结算；
3. 结算后回到飞船，确认大厅还在。

## 4. 需要记录/回传的东西

| 项 | 谁 | 怎么给 |
|---|---|---|
| 主持人侧：后端日志（`/opt/hd2-discovery/logs/` 或本机控制台输出） | 主持方 | 直接附在报告里 |
| 双方：`collect-logs.ps1` 生成的 zip | 双方 | 各自发回 |
| 关键时刻截图（创建大厅/加入/进局/报错弹窗） | 双方 | 发回 |
| 时间线（每个动作的本地时间，精确到秒） | 双方 | 写在回执里 |
| 抓包（主持人侧，可选） | 主持方 | pcap + `analyze_e2_capture.py` 输出 |

## 5. 失败止损顺序（按链路排查）

1. 游戏能进主界面但**看不到大厅** → 看后端日志有没有 `PUT /api/lobby` / `GET /api/lobby/accounts` 请求；
2. 能看到但**加入失败** → 看 `Party/RequestParty`、`Lobby/CreateLobby` 请求是否 200（PlayFab 云侧）；
3. 加入成功但**进不了局** → 看数据面：抓包判定走 Steam SDR 还是 PlayFab Party（`tools/analyze_e2_capture.py`）；
4. 任一步游戏异常/报错 → 先 `rollback-all.ps1` 还原，再收集日志，不带着改过的环境继续试。

## 6. 测试后（必须）

1. 双方 `collect-logs.ps1` → 发回 zip；
2. 双方 `rollback-all.ps1` → 确认回滚输出全绿；
3. 主持人停发现层服务（`systemctl stop hd2-discovery`）或保留待下次；
4. 回执模板：`结果（通过/失败）+ 卡在哪一步 + 双方时间线 + 日志 zip + 截图`。
