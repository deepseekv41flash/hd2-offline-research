## N1 购买/消耗写路径（S7 的具体化）— ✓ 需 mock 加写端点

**目标**：自建服玩家在军械库买东西/消耗战备时，客户端不崩、不重复扣、账本按响应或 `expectedCost` 兜底。

**为什么值得做**：自建服必踩路径。mock 现在对 `/api/Progression/…/purchase`、`/consume` 是 fallback `{}` —— 一旦玩家在自建服买东西，这是第一现场。

**做法**：mock 给这两个端点加"回显 + 幂等"实现（记录 `operationId`，重复请求返回同一结果），再让用户买一件最便宜的物品。

**判据**：① 游戏不崩/不卡 ② 战备/货币数量与 mock 回显一致 ③ 重复点击不重复扣（mock 日志出现 1 条 purchase） ④ 账本 `earned.purchases.count` +1 且 `recent_keys` 记下该 key。

**成本**：mock 改动约 1–2 h（含测试）+ 用户 10 min。

## N2 事件流：purchase / consume 该不该进 `settlements.jsonl` — ✓ 先观察后决策

**目标**：现在事件流只有 `settlement` 一种。购买/消耗是否也要进事件流（供外部统计/审计）？

**做法**：先做 N1，观察账本里 purchase 的落点；再决定是"新增 `event:"purchase"`"还是"维持只记账本"。

**判据**：不需要通过/失败，需要**一个产品决策**：外部工具是否需要逐笔购买记录。若需要，事件流 schema 要升到 2。

**成本**：决策 15 min；实现 2–3 h（若要做）。

## N3 一键回归（S3 + S1 的最小闭环）— ✓✓ 现在就能做

**目标**：把"起 mock → 起隔离引擎 → 打一局 → 判据"固化成一条命令，作为每次发版前的回归。

**做法**：`tools/regress_save_roundtrip.py`：起 mock（空数据集）→ 起引擎（隔离 state）→ 提示用户开一局 → 收尾自动跑 `save_state_snapshot diff` + `validate_save_export`。

**判据**：无人工判断项（脚本 PASS/FAIL）。

**成本**：3–4 h。价值：以后每次产品发版都能 1 条命令验证存档层没退化。

## N4 版本漂移抗性（旧产物喂新引擎）— ✓✓ 现在就能做（离线）

**目标**：`catalog_build` 变化 / 字段缺失 / schema 升级时，引擎读旧账本或旧导出产物会怎样？

**前置**：已有 `v0.7.0-alpha.1` 的导出产物（`D:\mod\tmp\save-export-sample`）+ 当前引擎（alpha.2）。

**做法**：① 人为删字段（去掉 `stats_profile_war`、去掉 `identity.hd2_account_id`）② 改 `catalog_build` ③ 用旧产物喂新 mock，看客户端表现与账本写回。

**判据**：缺字段不得导致崩溃/写坏账本；`catalog_build` 不匹配应有明确日志而不是静默按新目录解析。

**成本**：2 h，纯离线。

## N5 故障注入（上游病态响应）— ✓ 需 mock 加 fault 开关

**目标**：上游超时/500/半截 JSON/连接重置时，引擎与客户端是否优雅降级、账本是否被写坏。

**做法**：mock 加 `--fault path=模式:概率`（超时/Abort/半截 body），逐个端点试。

**判据**：① 游戏不崩或可重连 ② 账本不变或整档回滚（不得半写） ③ 日志有明确 WARN 而非静默 `{}`。

**成本**：3 h；与 N1 共用一部分 mock 改动。

## N6 A 机按玩家分档部署（真实网络路径）— ✓ 但**证书明天到期**

**目标**：在真实部署（hosts → A:443 → nginx → mock）上验证按玩家分档 + 存档互不干扰。

**前置**：A 机缺 `mock/players.py`（handler 仍是旧版 `6d86d00b…`），需部署 3 个文件 + 配 `players_dir` + 同步 `.deployed-rev`。

**⚠ 阻断项**：A 机证书 `83:0D:E2:87…` **2026-11-25 20:07 到期**——做这条前必须先决定"续证书"还是"用本机 TUN/端口转发代替"。**这是明天的硬约束，建议今天先把决定定下来。**

**判据**：按玩家分档在真实 TLS/反代下命中（`[player:<id>]`）、存档层与发现层不互相干扰（发现层 keys 命中率不掉）。

**成本**：部署 10 min + 测试 30 min + 证书决策。

## N10 存档导出往返一致性 — ✓ 取决于产品是否有导入

**目标**：`save-export` → （导入/换机）→ 账本是否逐字节一致。这是"迁移/备份"能力的地基。

**前置**：产品当前只有导出，没有导入。若要做导入，先定 schema（谁负责合并、冲突怎么解）。

**成本**：决策 30 min；实现视 schema 而定。
