# 阶段2 预检包（发给志愿者）与使用说明（2026-11-21）

> 背景：志愿者首轮环境报告除「hosts 不可写（脚本未提权）」外全部通过，且**游戏版本与我方基线逐字节一致**
> （buildid `26568081`、`helldivers2.exe` / `game.dll` 的 SHA256 相同，见
> [侦察结果](STAGE2-VOLUNTEER-RECON-RESULT-2026-11-21.md)）。本包用于让志愿者**以管理员身份**再实测一次改机能力，
> 并补齐版本/环境指纹，之后才发正式测试包。
> 三态：`✓✓ 实机` / `✓ 离线+数据` / `⚠ 未证` / `✗ 否证`。

## 1. 它做什么（与不做什么）

**做**：

1. 采集环境指纹：OS/版本/Insider/虚拟化、CPU/内存/磁盘、Steam 库与游戏 buildid、
   `helldivers2.exe` 与 `data\game\game.dll` 的**大小+SHA256 并与我方基线比对**、注入类残留、EAC 文件/服务、
   hosts 现状（含已有 Steam 屏蔽行）、网络（VPN 网卡/系统代理/WinHTTP/IPv6/防火墙/Defender）、系统时间与时区；
2. **canary 实测改机能力**：写入一行 hosts 测试标记 → 立即删除 → 校验 SHA256 与写入前一致；
3. 实测**当前用户根证书库是否可写**（决定能否免管理员装测试证书）；
4. 生成 `report-preflight-<主机>-<时间>.txt` 交给志愿者发回。

**不做**：不改游戏文件、不装证书、不启动游戏、不写注册表/服务、不上传任何数据。

## 2. 相对首轮报告的四处改进

| 改进 | 原因 |
|---|---|
| 启动器自动请求提权（`00-以管理员身份运行.bat` → `Start-Process -Verb RunAs`） | 首轮 FAIL 的唯一原因就是脚本未提权 |
| 提权失败时给出明确指引（去跑 `01-普通权限运行.bat` 并回报"标准用户"） | 区分「能提权」与「账户是标准用户」两种结论 |
| **多 Steam 库支持**（解析 `libraryfolders.vdf`，不假设游戏在主库） | 我方测试机就是 Steam 在 E:、游戏在 D: 的多库结构，首版因此误报"找不到游戏" |
| 版本比对内置期望值（buildid + 两个 SHA256） | 版本不一致会让整场实测白跑，必须在预检阶段判死 |

## 3. 志愿者操作（README 已写在包内）

1. 解压后右键 `00-以管理员身份运行.bat` → 以管理员身份运行（约 2 分钟）；
   若 Windows 要求输入管理员密码 ⇒ 说明是标准用户 ⇒ 取消，改跑 `01-普通权限运行.bat`；
2. 打开 `02-人工回答.txt` 填 5 个问题（Steam 好友、PSN 绑定、家庭共享、可用时间窗、测试前准备）；
3. 把生成的 `report-preflight-*.txt` 与 `02-人工回答.txt` 一起发回。

## 4. 我方收到报告后的分支

| 报告结论 | 下一步 |
|---|---|
| `ADMIN=True` + canary PASS | 部署发现层 → 出**正式测试包**（证书/hosts/回滚/测试卡）→ 约 E2 |
| `ADMIN=False`（标准用户） | 执行「系统代理 + 用户级证书」降级路线的本机对照实验（见设计档 §11.1） |
| 版本/哈希不匹配 | 让志愿者先 Steam 更新/验证文件，再重跑预检 |
| hosts 已有他人写入的行 | 保持不动；正式测试包只增删带我方标记的行 |

## 5. 隐私与安全

- 报告含主机名/路径等本机信息，**只走私聊**，不进公开仓；
- 本仓只记录脱敏结论（如「志愿者 ADMIN=True / buildid 一致」），不写主机名、路径、账户标识；
- canary 写入即还原，报告里会带「SHA256 与写入前一致」的自证。
